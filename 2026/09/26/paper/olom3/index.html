training = pretrain + posttrain

pretrain = pretraining + midtraining + longcontext

  1. pretraing -> 让模型学习通用的语言结构、世界知识和基本逻辑,“Next Token Prediction（预测下一个词）”的自监督方式训练。’

  2. Midtrain 是从通用预训练过渡到特定能力强化/对齐之前的高质量数据继续预训练阶段, 提升数据质量， 学习率衰减

  3. Long Context -> 将训练文本的序列长度拉长， 并配合位置编码(RoPE)的基频调整

post_train into 3 variants(后训练出三个变体)

  • Olmo 3 Think -> 生成结构化的CoT
  • Olmo 3 Instruct -> 对用户的查询高响应(效率优先)
  • Olmo 3 RL-Zero -> 开源

Q3：Q_heads 为什么能和 KV_heads 数量不一样
这种 Q 和 KV 头数不相等的机制叫做 GQA（Grouped-Query Attention，分组查询注意力）
每个头对应的dimension还是不变的， 但是K,V (batch_size, n_head = 8, seq_len, dim), Q(batch_size, n_head = 40, seq_len, dim), Q5个头为一组去分别查询K，V

Query (Q)：代表提问者的视角/需求。即使问题很复杂，我们希望有 4 个不同维度的专家（4 个 Q 头）去提问。Key/Value (K/V)：代表图书资料库的检索索引和内容。传统 MHA：为 4 个专家各自配备一套独立的图书馆资料库（4 套 KV）。GQA 机制：专家 0 和专家 1 共享同一套资料库 0，专家 2 和专家 3 共享同一套资料库 1。

显著的好处是减少了KV cache， 让显存占用明显减少

Q4: sliding window attention是个什么东西
为了支持在更长序列长度上的可扩展预训练，同时控制推理成本，我们引入滑动窗口注意力（SWA）模式（Beltagy et al., 2020），其中每个令牌可以关注窗口中大小为 4096 的前序令牌。我们在每四层中的三层加入 SWA，并确保最后一层始终使用全注意力
全用全注意力在长上下文非常耗算力

Pretraining_data

标准：我们遵循两条主要原则来指导数据策略：（i）只有当一个数据源有潜力产出足够多的令牌、能够在预训练规模上影响模型能力时，我们才考虑将其用于预训练

MidTrain

在此中期训练阶段，我们使用 100B 高质量令牌

更有意识地纳入指令数据与思维轨迹这两类数据

此得到的中期训练数据是一个多样化的混合，将新颖的合成来源与预训练阶段的数据相结合，但经过了质量过滤与重写，以更好地适配我们在该阶段所针对的能力

在退火期，模型已经固定，lr比较少， 这时候输入的数据能被很高效地吸收

Q1：pretraining和midtrain除了数据之外在训练架构上有什么不同
进入 Midtraining 时，学习率会经历快速的指数/余弦衰减（Decay / Annealing），通常会骤降至初始峰值学习率的 1/101/101/10 甚至更低

Q2：怎么用小数据量知道midtrain特定任务的效果

  • 微退火法

实验组：在 5B 数学题 + 5B 网页文本 上快速训练，得到模型 A。对照组（基线）：在 10B 纯网页文本 上做一模一样的快速训练，得到模型 B。

如果模型 A 的数学成绩比模型 B 高很多，说明这个数学题库真的有额外贡献（高净增效益）。

我们在中期训练期间针对五项核心能力：改进数学与编码、通过 QA 更好地激发知识、以及在进入后训练阶段之前引导指令遵循与推理能力

Q3：midtrain和post-train有什么区别呢??
机制上：midtrain还是采用autoggressive , 标准的预测下一个词的更新全部参数。 但post_train只对Answer计算损失， 一般不改动全部参数

数据形态：即用 50%~80% 的高质量专业数据，加上 20%~50% 的普通网页通用数据。这样做的目的是防遗忘。并且这些高质量数据也不结构化。 Post-training纯粹针对特定任务/指令场景，高度结构化

Long-context Extensions

我们概述将 Olmo 3 的上下文窗口从 8192 扩展到 65,536 令牌所用方法的概览

长上下文扩展策略——由于用长序列长度训练计算成本高昂，大多数语言模型以较短序列预训练，并仅在模型开发的后期阶段进行扩展。在扩展阶段，模型在更长的文档上训练，并且通常调整位置嵌入的超参数以缓解位置泛化问题

架构

长上下文扩展期间，我们对全注意力层应用 YaRN（Peng et al., 2023），且不调整滑动窗口注意力层上的位置嵌入；我们使用文档打包（document packing）与文档间掩码

Q1:没有长上下文模型的情况下， 怎么创造合成数据
大海捞针”与长距离依赖合成：收集大量无关但语言通顺的普通长网页文本（如 32K 长度）。信息植入（Needle）：在文本的中前部随机位置精准插入一条或几条特定信息（例如：“秘密密码是：X972K-Alpha” 或假想的规则约定）。末端提问（Question）：在 32K 文本的最后提出针对该信息的复杂问题（例如：“结合前文所有的规则，计算最终提取出来的授权码是什么？”）

Q2: 模型本身的架构会在这一个阶段怎么变化
用YarN的方式改变RoPE
分频段针对性处理:高频通道（High Frequencies）：旋转极快，主要捕捉相邻词/局部语法。YaRN 决定完全不缩放（不压缩）它们，以保留模型原生的局部语言感知能力。
低频通道（Low Frequencies）：旋转极慢，主要捕捉跨段落/全局长距离依赖。YaRN 对这部分进行完全内插/压缩。
位置内插:让一个上下文θ刚好旋转一圈

中频通道（Medium Frequencies）：介于两者之间，采用平滑过渡（Smooth Interpolation）。

注意力温度修正引入一个温度缩放因子 γ\gammaγ（重缩放 Softmax 的 logits），重新拉高注意力的峰值
