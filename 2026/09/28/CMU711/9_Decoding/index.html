Decoding

有点类似tree_search

优化解码

y = argmax(y)(pθ(y|x))

  • scoreing = pθ(y|x)

  • MAP
    $$\hat{Y} = \arg\max_{Y} P(X \mid Y) P(Y)$$

  • $P(X \mid Y)$（似然度 / Likelihood）： 在给定生成序列 $Y$ 的情况下，观察到输入 $X$ 的概率（如声学模型或信道模型）
  • $P(Y)$（先验概率 / Prior）： 输出序列本身符合语言规范的概率（如语言模型 Language Model）

  1. greedy decoding -> 每一步都选择最大可能的token
    但是这很可能输出的不是最高概率的sequence

  2. beam search -> maintain several likely paths

beam_size = 2 -> 维护两个最高可能的路径

一般的beam_size = 16,32

  • Hugging face interface

Pitfalls

  1. Highest ≠ best
  2. 容易出现短句, 重复的句子 ->
    在lossfunction中加入重复惩罚
    length nomalization -> 因为查看MAP原理的话， 结束符号很容易就变成最高的概率，所以我们还要对短句进行惩罚
  3. atypicalty(典型性) -> 我们得到的所有序列可能性都很小， 我们可能很少概率获得概率最高的方法，比如就是sequence (), 所以highest ≠ best

采样解码

现在基本都是使用sampling

  1. next_token_sampling(我们只预测下一个)
  2. categorical sampling
  • bad effects
    compouding error -> 长序列会出现bad tokens
  • 解决办法 truncate the tail
  • Top-k: 我们只会从最大5个概率最大的token取样
  • Top-p: 前面累计概率大于p， 后面就会被截断
  • ε ： 小于某个概率滚蛋

Temperature sampling

  • 让分布峰度更大

让τ < 1 ： 分布更尖锐

Q:我们不应该有一个效能函数，让它更好的总体遵守这个函数吗
调整 Temperature、Top-$k$、Top-$p$ 这些采样参数，本质上只是在“随机性（探索/多样性）”与“高概率（确定性/流畅度）”之间做粗暴的硬截断或平滑权衡（Trade-off）。它们属于启发式的局部采样策略，并不直接对“最终生成序列的质量”或“具体目标的达成效果”负责。

可用的方法

强化学习，用奖励函数（Reward Model, RM）作为效能函数：定义一个效能函数 $R(Y \vert{} X)$，评价针对输入 $X$，生成的序列 $Y$ 有多好（比如：代码是否能跑通、回答是否安全、文风是否贴切）。

推理阶段的搜索与重采样（Decoding Time Alignment / Best-of-N）—— 在生成时用效能函数筛选
机制：用 Temperature > 0 采样生成 $N$ 个不同的候选序列 $Y_1, Y_2, \dots, Y_N$。评价：用你的效能函数 $U(Y)$ 给这 $N$ 个序列打分。输出：选择得分最高的序列：

约束解码与控制生成（Guided / Constrained Decoding）—— 在生成词的瞬间用效能导向调整概率

加速推理

  1. 我们需要前文(1:t) 的 K， V 矩阵（KV CACHE）
  1. 内存：内存加载写回(会很影响)

由计算速度和内存加载速度的最大值决定

指数:

  1. Lantency -> time to first token
  2. throughput -> how many requests are completed per second 不同请求可以在同一个batch里面
  3. quality -> 输出的质量

Lantency

  1. reduce memory bandwidth -> 内存载入速度
    量化，蒸馏，架构元素
    GPTQ,AWQ（lecture 19）
  2. Increase FLOP/s
    flash attention (lecture 22), kernel fusion
  3. reduce FLOPS 减少计算量
    Mixture of Experts(lecture 21), Mamba(lecture 22)

throughtout -> speed up a full sequence

  1. speculative decoding(投机编码)
  • 用cheap的模型autoggressive生成一连串候选token(多的token)，大模型负责审核这几个token, 并且打分， 一位内大模型只需要一次传播就能生成好几个cheap模型的token

因为把这几个token全加到前缀里面，一次token前向传播， 我们可以把这几个token的下一个概率分布全部算出来

  1. None_autoggressive models(diffusion)
  • 可以同时生成好几个token

speed up multiple seqs

  1. state re-use (前缀相同的可以共享kv cache)
    pagedAttention, RadixAttention(SGLang)

  2. improved batching

  3. Program-lebel optimzation
