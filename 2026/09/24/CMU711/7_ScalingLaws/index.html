Scaling Laws

决定了 -> How many tokens, batchs size, learning rate

Compute（算力资源）

算力被消耗在前向反向传播中

单位是（FLOPS，floating points operation）

C = 6 * N * D（适用于训练过程）

  • N : 参数量
  • D ： 数据量
  • 算力是六倍的参数量 * 数据量

Scaling Laws

L -> Cross-Entropy

Cross-Entropy Loss 是被数据集决定下限的， 随着parameters越老越多， 会有一个趋向data熵值的趋势

用log - log图表呈现

repeating data 4 epoches is good enough -> 多了的话边际效应很明显
在4 epoched内， 用重复数据降低的loss几乎等同于用新的数据

L(N,D)=E+ANα+BDβL(N, D) = E + \frac{A}{N^\alpha} + \frac{B}{D^\beta} L(N,D)=E+​N​α​​​​A​​+​D​β​​​​B​​

Using scaling laws to choose hyperprameters

  1. run many experiments at a small scale
  2. using scaling law to estimate the best hyper parameters for larger scaling

[Chichilla论文]:

  1. run experiments
  2. fit a line in the log-log plots and predict hte optimal model size and tokens
    *这个图标是X 是log算力， Y是 log数据量或者参数量

batch_size , learning_rate等超参数也有随着FLOPs的scaling laws

Recap:SCALING LAWS是一系列揭示变量和perfoemance之间的公式，一般遵循幂律，也就是LOG-LOG上的线性

Prompting

我们想要输出， 我们给定一个输入让它最大化后面那个输出的可能

  • Aside: Generation
  1. 如果没有format prompt
  • 它会补充输入的内容
  1. zero shot(给它指示让它行动)
  • 这个需要详细的Fine-tuning
  1. few shots(给它指示和例子)
  • prompt:f(x_test, instructions, [(x,y)1, (x,y)2, …])
  • IN-CONTEXT LEARNING -> 没有任何参数更新

在大规模的预训练的时候，模型已经见过IN-CONTEST LEARNING所要求的任务， 所以它并不会学习新的任务，所以一般没有给特定示例的ICL 会 达到更高的准确率

为了防止它只是从原来的任务中检索， 我们可以用Reinforcement ICL

  • 如果给更多的示例会让更准确吗？

  • 会的， 甚至可以达到和default差不多

语言模型对上下文学习（In-Context Learning）中的微小变化非常敏感,比如示例的顺序变化就会造成很大的改变

说明ICL 不够健壮（robust）
