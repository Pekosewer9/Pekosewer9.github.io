Base Model + Task Data --Fine-tuen–> Translation

Fine_tuning

继续基于梯度的对预训练模型的训练

  1. 预训练参数 θ

  2. 给训练数据D

  3. (\theta^* = \operatorname*{argmin}{\theta} \mathbb{E}{(x,y)\sim D} \left[ \mathcal{L}(f_{\theta}(x), y) \right])

  4. 加上比如dropout/Regulation/weight_decay的技术防止overfitting

这被叫做SFT

Example:Classification

  1. 我们会从Autoaggressive或者maskedmodel中获得hidden layer的变量
    f(x1…xT) = h1 … hT

  2. 我们用h_T， 最后一个hidden layer的方式表征句子的意思

  3. p(y|x) = softmax(Wh + b) b的维度是分类的种类

  4. Loss = 交叉熵

  5. 更新所有梯度， 包括后来的(W，b) 和 预训练模型里面的θ

  • 注意如何得到最后一个hidden layer: (要考虑attention会不会被mask)

完整版见Fine_tuning_classification。ipynb

LLM fine_tuning

  • 不再是分类任务， 而是自回归任务
  1. Create dataset and follow the format like:

Format: <|startoftext|>Reverse the name: emma. Answer: amme<|endoftext|>

  1. 加上一个额外的 linear layer，输出维度是vocab_size

  2. train like ususal and no need to apply other layers

Q: should I fine_tune all parameters

  1. update only output head(W,d)
  • 前提：预训练的语义输出已经足够支持任务
  1. update all parameters
  • Expensive
  • overfit (use valid , lessen the epoches)
  • 会改变语义表达， 可能会减弱其他的任务
  1. update small number of parameters inside the model
  • 我们只改变原来参数中的一点
  • 我们称其为Parameter-efficient fine-tuning(PEET)

LoRA

w0 = R(d * d’)

A = W0 + α/r * B ` A
alpha类似学习率

B = R(d * r) A = R(r * d’) r << min(d, k)

only update B & A during fine_tuning

经常做法， 把LoRA layer放在attention layers中

仅 Query 与 Value（$W_q, W_v$）：最经典、最节省显存的配置（例如原始 LoRA 默认配置）。早期微调通常只在这两个矩阵上加 LoRA，就能用极少的参数量取得相当不错的拟合效果。

主流全面配置：Attention + MLP（全线性层）
随着大模型技术的发展（尤其是社区如 LLaMA-Factory、PEFT 的推广），将 LoRA 施加到模型中所有的 Linear（线性）层已成为当下的主流推荐标准。

问题：如果LLM的预训练数据已经包含了Fine_tuning数据集的数据，那么Fine_tuning还有意义吗

微调（尤其针对特定领域的 SFT）就像给模型建立一个高效的提取索引（Routing / Trigger Mechanism）。通过少量高质量的微调数据，可以把模型在预训练时就已经学到的相关知识“唤醒”并拉到概率输出的前列。

  • 也就是more data-efficient

  • narrow the Dkl(p_data_finetuning, pθ)

  • 但是训练和输入需要严格的format约束

[我们可以在huggingface上寻找不同的data]

knowledge distillation(蒸馏)

Teacher model: better LLM

student model: smaller model

  1. Token_level knowledge distillation
    在训练过程让student model的输出接近teacher model

[hinton et al 2015]

  • 但是我们必须改变原来的softmax，因为我们不知道teacher model输出的概率分布(蒸馏实际上就是用输出信息的高密度来弥补student model参数少的缺陷，因为参数少空间里容易非凸，陷入局部最小，所以需要更多高密度数据来让空间平滑)
  • tokenizer必须是一样的
  1. sequence-level knowledge distillation

prompt - Teacher -> response

base model(prompt,response) --Fine_tuning–> student

就是把teacher的输出输入变成数据集来Fine_tuning student model

  1. augmented language model

我们可以把teacher的输出进行用一个fliter（classifier, vertifiler）筛选， 可以让student 模型做的更好

[OLMo: Accelerating the Science of Language Models]

如果把模型做的够小小到不足以表示世界， 但让模型用相对大的数据去表征世界， 会不会有一些结果
